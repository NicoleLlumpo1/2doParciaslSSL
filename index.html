⭐ Palabras clave y palabras reservadas

  • Palabra clave (keyword): secuencia de letras con significado especial para el lenguaje (if, while, int).
  • Palabra reservada: palabra clave que no se puede usar como identificador.
  • En C todas las palabras clave son reservadas. En otros lenguajes (Fortran, PL/I) hay keywords que no son reservadas: IF IF = THEN era válido en PL/I.
  • Las palabras clave sintácticamente parecen identificadores: cumplen la misma ER [A-Za-z_][A-Za-z0-9_]*.
Palabras clave de C (K&R A2.4, ANSI C):
auto break case char const continue default do double else enum
extern float for goto if int long register return short signed
sizeof static struct switch typedef union unsigned void volatile while

Agregadas en estándares posteriores: inline, restrict, _Bool (C99);
bool, true, false, nullptr, constexpr, typeof (C23) → verificá cuáles ve tu cátedra.

Cómo lo resuelve el scanner

  • Reconoce el lexema con la ER de identificador (regla del match más largo: integer es un identificador, no int + eger).
  • Luego busca el lexema en una tabla de palabras reservadas; si está, devuelve su token (INT, IF…); si no, IDENTIFICADOR.
  • En flex: si hay empate de longitud, gana la regla escrita primero, por eso las keywords van antes que la regla de identificador.

Ojo: printf o NULL no son palabras clave: son identificadores de la biblioteca estándar. Tampoco podés definir identificadores que empiecen con _ + mayúscula o con __: están reservados para la implementación.

Ejercicio: ¿cuáles son identificadores válidos? for, For, _for, 2for, sizeof_x

For, _for y sizeof_x son identificadores válidos (C distingue mayúsculas y el match más largo hace que sizeof_x no sea sizeof). for es palabra reservada. 2for empieza con dígito: es un error léxico (se lee 2 y luego for).

Casos típicos de UB

int x = INT_MAX; x + 1;        /* overflow de entero CON signo */
1 / 0;                          /* división por cero */
int *p = NULL; *p = 5;          /* desreferenciar puntero nulo */
int a[3]; a[3] = 1;             /* acceso fuera de límites */
int u; printf("%d", u);         /* leer variable no inicializada */
i = i++ + 1;  a[i] = i++;       /* modificar un objeto dos veces sin secuenciar */
1 << 40;                       /* desplazar ≥ ancho del tipo (int de 32 bits) */

Conexión con tus trabajos

  • TP2, overflow: la suma de int que desborda es UB; en cambio los unsigned dan la vuelta (módulo 2ⁿ), que está definido. Por eso hay que detectar el desborde antes de sumar.
  • Orden de evaluación: f()+g()+h() es comportamiento no especificado (no UB). i = i++ + 1 sí es UB.
  • K&R 2.12: printf("%d %d\n", ++n, power(2, n)); depende del orden de evaluación de los argumentos.

Frase para el parcial: "Un programa con comportamiento indefinido no es un programa C correcto; el compilador puede asumir que no ocurre y optimizar en consecuencia."

Ejercicio: clasificá cada caso (indefinido / no especificado / definido por implementación)
  • int a = f() + g(); → no especificado (orden de f y g).
  • int n = 5; n = n++ + ++n; → indefinido (modifica n dos veces sin secuenciar).
  • sizeof(long) → definido por la implementación.
  • unsigned u = 0; u--; → definido (módulo 2ⁿ).
  • a[10] en int a[10] → indefinido (fuera de límites).

⭐ Gramáticas formales

G = (N, T, P, S): N = no terminales, T = terminales (N ∩ T = ∅), P = producciones, S ∈ N = axioma.

  • Derivación directa α ⇒ β: se aplica una producción una vez. Derivación α ⇒* β: cero o más pasos.
  • Forma sentencial: cualquier cadena derivable desde S (puede tener no terminales). Sentencia: forma sentencial solo con terminales.
  • Lenguaje generado: L(G) = { w ∈ T* | S ⇒* w }.
  • Derivación más a la izquierda / más a la derecha: se reemplaza siempre el no terminal de ese lado.
  • Árbol de derivación: raíz S, hojas terminales leídas de izquierda a derecha = la sentencia.
  • G es ambigua si existe una sentencia con 2 o más árboles de derivación (o 2 derivaciones más a la izquierda distintas).
  • Dos gramáticas son equivalentes si generan el mismo lenguaje. Una ambigua puede tener una equivalente no ambigua; hay lenguajes inherentemente ambiguos.

Ejemplo: G = ({S}, {a, b}, {S → aSb | ab}, S)

Genera L = { aⁿbⁿ | n ≥ 1 }. Derivación de aaabbb: S ⇒ aSb ⇒ aaSbb ⇒ aaabbb. Es libre de contexto (tipo 2), no regular.

Ejercicio 1. Gramática regular para (a|b)*ab 
G = ({S, B}, {a, b}, P, S)
P: S → aS | bS | aB
   B → b

Derivación de bab: S ⇒ bS ⇒ baB ⇒ bab. Todas las producciones son de la forma A → aB | a: tipo 3.

Ejercicio 2. Demostrá que E → E+E | E*E | id es ambigua

Sentencia id + id * id, dos árboles:

Árbol 1: (id + id) * id          Árbol 2: id + (id * id)
      *                                +
     / \                              / \
    +   id                          id   *
   / \                                  / \
 id   id                              id   id

Solución: separar en niveles (E → E+T | T ; T → T*F | F ; F → id), que fija precedencia y asociatividad.

Ejercicio 3. ¿Qué tipo de Chomsky es S → aSb | ε ? ¿Y aA → bAa?

S → aSb | ε: tipo 2 (lado izquierdo = un solo no terminal), no es tipo 3 porque el no terminal está en el medio. aA → bAa: lado izquierdo con contexto (más de un símbolo): tipo 1 si no acorta la cadena.

1. Expresiones Regulares

Una ER describe un lenguaje regular (Chomsky tipo 3). Se arman con tres operaciones básicas sobre un alfabeto Σ:

  • Unión a|b → {a, b}.
  • Concatenación ab → {ab}.
  • Clausura de Kleene a* → {ε, a, aa, aaa, …} (cero o más). La clausura positiva a+ = aa* (una o más).

ER extendidas (ERX / Regex)

Son azúcar sintáctico: no agregan poder expresivo (siguen siendo regulares), pero abrevian.

  • Entero con signo opcional: [+-]?[0-9]+
  • Binario par: (0|1)*0
  • Cadenas con "ab" como subcadena: (a|b)*ab(a|b)*

3. Lenguaje C: identificadores y declaraciones (K&R A8)

  • Identificador: letras, dígitos y _; no empieza con dígito; distingue mayúsculas; no puede ser palabra reservada.
  • Declaración = especificadores + lista de declaradores con inicializador opcional.
  • Especificadores: clase de almacenamiento (auto, register, static, extern, typedef), tipo (int, char, struct…) y calificadores (const, volatile).
  • Declaradores: * (puntero), [] (arreglo), () (función).
int *p[10];     /* arreglo de 10 punteros a int */
int (*q)[10];   /* puntero a arreglo de 10 int  */
int (*f)(int);  /* puntero a función int→int    */
char *(*g[3])(void); /* arreglo de 3 punteros a función que devuelven char* */

Para leer: empezá por el identificador y andá a la derecha ([], ()) antes que a la izquierda (*), respetando los paréntesis.

Distinguí los tres conceptos

  • Precedencia: qué operador se agrupa primero (a+b*c → a+(b*c)).
  • Asociatividad: cómo se agrupan operadores de igual precedencia (a-b-c → (a-b)-c).
  • Orden de evaluación: en qué orden se evalúan los operandos. C no lo especifica para casi todos los operadores (solo && || ?: , lo garantizan). En f()+g() no sabés cuál se llama primero.

5. Gramáticas, Jerarquía de Chomsky y Autómatas

Gramática formal G = (N, T, P, S): no terminales, terminales, producciones y axioma.

TipoGramáticaForma de producciónReconocedor
0Sin restriccionesα → βMáquina de Turing
1Sensible al contextoαAβ → αγβAutómata linealmente acotado
2Libre de contextoA → γAutómata con Pila (AFP)
3RegularA → aB | aAutómata Finito (AF)

AFD

M = (Q, Σ, δ, q0, F) con δ: Q × Σ → Q (función total, un solo camino por cadena). Acepta si termina en un estado de F.

AFP

M = (Q, Σ, Γ, δ, q0, Z0, F): agrega una pila (alfabeto Γ, símbolo inicial Z0). Cada transición mira estado, símbolo de entrada y tope de pila, y puede apilar/desapilar.

Por qué hace falta la pila: L = { aⁿbⁿ | n ≥ 1 }

Un AF no puede "contar" ilimitadamente. El AFP apila una A por cada a y desapila una por cada b; acepta con la pila en Z0. Mismo motivo por el que los paréntesis balanceados y las expresiones anidadas necesitan gramáticas tipo 2.

Relación clave: regex ⇔ gramática regular ⇔ AF (léxico / scanner). BNF ⇔ gramática libre de contexto ⇔ AFP (sintaxis / parser).

6. Análisis sintáctico descendente recursivo, BNF y expresiones

BNF y su historia

  • BNF (Backus-Naur Form): notación para gramáticas libres de contexto, usada por primera vez para definir ALGOL 60. Formato: <no-terminal> ::= alternativa | alternativa.
  • Pascal (Wirth) se definió con diagramas sintácticos y EBNF, que agrega { } (repetición) y [ ] (opcional).
  • Identificadores: <identifier> ::= <nondigit> | <identifier> <nondigit> | <identifier> <digit>.

Expresiones con precedencia y asociatividad en la gramática

La precedencia se codifica por niveles (más abajo = más fuerte) y la asociatividad por el lado de la recursión.

<expression> ::= <term> | <expression> '+' <term>        /* + asocia a izquierda */
<term>       ::= <primary> | <term> '*' <primary>
<primary>    ::= IDENTIFICADOR | NUMERO | '(' <expression> ')'

Parser descendente recursivo (PAS)

  • Una función por cada no-terminal. El cuerpo sigue la producción.
  • Necesita un token de lookahead para elegir alternativa (gramática LL(1)).
  • No tolera recursión a izquierda (loop infinito). Se elimina: E → E+T | T pasa a E → T { + T }.
void Expression(void){          /* E → T { '+' T } */
    Term();
    while (token == SUMA) { Match(SUMA); Term(); }
}
void Term(void){                /* T → P { '*' P } */
    Primary();
    while (token == PRODUCTO) { Match(PRODUCTO); Primary(); }
}

Nivel léxico y Scanner

Nivel sintáctico y Parser

  • BNF tipo Bison; axioma translation-unit.
  • Un Parse<NoTerminal> por cada no-terminal; el parser llama al scanner (GetNextToken) y a rutinas semánticas.
  • Scanner y parser separados lógicamente (Scanner.c/h, Parser.c/h, main.c).

  • Semántica especificada en lenguaje natural: el valor de una constante, el de una suma/producto, qué pasa con un identificador.
  • Errores: léxico (carácter inválido), sintáctico (token inesperado, ej. 42+), semántico (reglas que la gramática no puede expresar).
  • Válidas: A+2*3, 2*A+3, A, 2. Inválidas: +, 42+, +A.

d. Definición formal del AF

e. GetNextIdentificador (prototipo, invocación, implementación) 
/* i. prototipo */
bool GetNextIdentificador(FILE *s, char *id, size_t max);

/* ii. invocación */
char buf[32];
if (GetNextIdentificador(stdin, buf, sizeof buf))
    printf("Identificador: %s\n", buf);

/* iii. máquina de estados (enum + switch) */
bool GetNextIdentificador(FILE *s, char *id, size_t max){
    enum { Inicial, EnIdentificador } estado = Inicial;
    int c; size_t n = 0;
    while ((c = getc(s)) != EOF) {
        switch (estado) {
        case Inicial:
            if (isspace(c)) break;
            if (isalpha(c) || c == '_') { id[n++] = c; estado = EnIdentificador; }
            else { ungetc(c, s); return false; }
            break;
        case EnIdentificador:
            if ((isalnum(c) || c == '_') && n < max - 1) id[n++] = c;
            else { ungetc(c, s); id[n] = '\0'; return true; }
            break;
        }
    }
    if (estado == EnIdentificador) { id[n] = '\0'; return true; }
    return false;
}

Parte 2 – Gramática (selection-statement)

a. Formalizar la gramática

G = (N, T, P, S) con:

  • N = { <selection-statement>, <expression>, <statement> }
  • T = { "if", "(", ")", "else", … terminales de expression y statement }
  • S = <selection-statement>
  • P = las dos producciones del BNF dado (con if, y con if-else), más las de <expression> y <statement>, que incluye a <selection-statement>.
b. Sentencia correcta y derivación

Sentencia: if (x) y; (suponiendo <expression> → identificador y <statement> → expresión ";")

<selection-statement>
⇒ "if" "(" <expression> ")" <statement>      (1ª producción)
⇒ "if" "(" x ")" <statement>                  (expression → x)
⇒ "if" "(" x ")" y ";"                       (statement → y ;)
c. ¿Es ambigua?

Sí, es ambigua (problema del dangling else). La cadena if (a) if (b) s1; else s2; tiene dos árboles de derivación:

  • El else pertenece al if (b) (el interno).
  • El else pertenece al if (a) (el externo).

Una gramática es ambigua si existe una cadena con más de un árbol de derivación. C lo resuelve por regla semántica: el else se asocia con el if más cercano.

Semántica de f()+g()+h()

a, b, c. Operaciones, orden y restricciones

a. Operaciones: 5. Tres invocaciones de función (operador ()) y dos adiciones. Por asociatividad izquierda: (f()+g())+h().

b. Orden: C no especifica el orden de evaluación de los operandos de +. Solo se garantiza que cada suma se realiza después de evaluar sus dos operandos: la primera suma necesita f() y g(); la segunda necesita esa suma y h(). Pero h() podría llamarse antes que f() o g().

c. Restricciones semánticas (dos):

  • f, g y h deben estar declaradas y ser funciones (o punteros a función).
  • Cada función debe devolver un tipo aritmético (no void), para que + sea válido. Además, la cantidad y tipos de argumentos deben coincidir con el prototipo.

9. Ejercicios extra: AFP y BNF

Notación AFP: δ(estado, entrada, tope) = (estado nuevo, qué se apila). Con ε = sin consumir entrada o sin apilar.

Autómatas con Pila

Ejercicio 1. AFP para L = { aⁿbⁿ | n ≥ 1 }

M = ({q0, q1, q2}, {a, b}, {A, Z}, δ, q0, Z, {q2})

δ(q0, a, Z) = (q0, AZ)    /* primera a: apila A */
δ(q0, a, A) = (q0, AA)    /* más a: apila A */
δ(q0, b, A) = (q1, ε)     /* primera b: desapila */
δ(q1, b, A) = (q1, ε)     /* más b: desapila */
δ(q1, ε, Z) = (q2, Z)     /* pila vacía (solo Z): acepta */

Traza con aabb: Z → AZ → AAZ → AZ → Z → acepta.

Ejercicio 2. Paréntesis balanceados

M = ({q0, q1}, {(, )}, {P, Z}, δ, q0, Z, {q1})

δ(q0, (, Z) = (q0, PZ)
δ(q0, (, P) = (q0, PP)
δ(q0, ), P) = (q0, ε)
δ(q0, ε, Z) = (q1, Z)

Si aparece ) con Z en el tope: no hay transición y se rechaza. Si termina con P en la pila: tampoco acepta.

Ejercicio 3. Idea del AFP para L = { w c wᴿ | w ∈ {a,b}* }
  • Antes de la c: apilar cada símbolo leído.
  • Al leer c: pasar al estado de comparación sin tocar la pila.
  • Después de la c: cada símbolo leído debe coincidir con el tope y se desapila.
  • Acepta cuando queda solo Z. Es determinístico gracias a la marca c; sin ella (palíndromos puros) el AFP es no determinístico.

BNF y derivaciones

Ejercicio 4. BNF de expresiones con + - * / y paréntesis (asociativos a izquierda) 
<expression> ::= <term>
               | <expression> '+' <term>
               | <expression> '-' <term>
<term>       ::= <factor>
               | <term> '*' <factor>

<identifier-list> ::= <identifier>
                     | <identifier-list> ',' <identifier>

En EBNF: identifier { ',' identifier }. En regex (a nivel léxico): ID(,ID)*.

Ejercicio 7. Eliminar la recursión a izquierda para un parser descendente

Regla: A → Aα | β se transforma en A → βA' y A' → αA' | ε.

E  → T E'
E' → '+' T E' | ε
T  → F T'
T' → '*' F T' | ε
F  → IDENTIFICADOR | NUMERO | '(' E ')'

Atención: al implementar E' como bucle, mantené la asociatividad a izquierda al evaluar (acumulá el resultado).

Ejercicio 8. Eliminar la ambigüedad del dangling else 
<statement>  ::= <matched> | <unmatched>
<matched>    ::= "if" "(" <expression> ")" <matched> "else" <matched>
                | <other-statement>
<unmatched>  ::= "if" "(" <expression> ")" <statement>
                | "if" "(" <expression> ")" <matched> "else" <unmatched>

Entre un if y su else solo puede haber sentencias "matched": el else queda ligado al if más cercano.
